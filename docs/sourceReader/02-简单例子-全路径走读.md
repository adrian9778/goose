# 02 · 简单例子：全路径走读

> 层级：L2 简单例子 · 本文沿一条真实最小成功路径，从 CLI 入口追踪到 agent 回复，只走主成功路径，不展开状态机内部各 operation 细节（见 03）。

## 场景

终端执行 `goose run "给一个例子"`（headless 非交互，GooseMode 为 `Auto`，无工具调用，模型一次返回文本）。这是最短、覆盖核心链路的一条真实路径。

## 逐步走读（参数与关键动作）

### 1→2 · 进程与 CLI 入口

`main()`（`main.rs · main+0`）建 8MB 栈线程跑 tokio runtime（`main+8`，multi_thread + enable_all），`block_on(run())`。`run()`（`run+0`）先 `setup_logging`，可选 `model_catalog::initialize`（feature online-model-meta），然后 `cli().await`。`cli()`（`cli.rs · cli+0`）`Cli::parse()` 解析参数，`match cli.command` 分发到 `Command::Run` 分支（`cli+89`），调用 `handle_run_command`。

### 4→6 · Run 命令处理

`handle_run_command`（`cli.rs · handle_run_command+0`）：
- 若 `interactive` 且未选过 telemetry 则弹 consent（`handle_run_command+10`）；
- `parse_run_input(&input_opts, output_opts.quiet)`（`handle_run_command+14`）解析 stdin/文件/参数得到 `InputConfig { contents, additional_system_prompt }`；
- 校验 `--session-id` 只能配 `--resume`（`handle_run_command+20`）；
- `goose_mode = Config::global().get_goose_mode()`（`handle_run_command+31`，本例 Auto）；
- `get_or_create_session_id(...)`（`handle_run_command+32`）：headless 无 `--resume`、无 `--no-session` 时 `session_manager.create_session(current_dir, "CLI Session", SessionType::User, mode)` 建会话，返回 `session_id`；
- 组 `SessionBuilderConfig`（`handle_run_command+40`），内含 extensions、builtins、model_opts、recipe 等。

### 7→11 · 会话构建

`build_session`（`builder.rs · build_session+0`）→ `try_build_session`（`try_build_session+0`）：
- `StateMachineServices::with_config(StateMachineServicesConfig::cli())`（`try_build_session+5`）：`cli()`（`services.rs · cli+0`）用进程单例 `SessionManager::instance()`、`PermissionManager::instance()`，`goose_platform=GooseCli`。`with_config`（`services.rs · with_config+0`）构建 `ExtensionManager`、`tool_inspection_manager`、`SessionRuntime`，并 `runtime.runs.set_services`。
- `resolve_provider_and_model`（`builder.rs · resolve_provider_and_model+0`）：本例 provider_name 取 `session_config.provider`→`saved_provider`→`recipe_settings`→`configured_provider`→registry default（`resolve_provider_and_model+12~+21`）；model_name 类似解析（`resolve_provider_and_model+77`）。返回 `ResolvedProviderConfig { provider_name, model_config }`。
- `CliSession::new(services, session_id, ...)`（`session/mod.rs · new+0`）：`session_manager.get_session(&session_id, true)` 读会话得 `messages = conversation`，建 `completion_cache`，可配 `extension_loading` 后台句柄。

### 12→14 · headless 入口

`headless`（`session/mod.rs · headless+0`）：`Message::user().with_text(&prompt)` 构造用户消息，调 `process_message(message, cancel, false)`（`process_message+0`）。`process_message` 先 `ensure_extensions_loaded(false)`（`process_message+6`，扩展加载 gate，本例无扩展立即通过），再 `push_message`、`process_agent_response`。

### 15 → push_message

`push_message`（`session/mod.rs · push_message+0`）把 `message` 推进 `self.messages`（`Conversation`）。

### 16 → process_agent_response

`process_agent_response`（`session/mod.rs · process_agent_response+0`）：
- 组 `SessionConfig { id, schedule_id, max_turns }`（`process_agent_response+8`）；
- 拿最后一条 user message（`process_agent_response+13`）；
- 起 ctrl_c 监听任务，`cancel` 触发中断（`process_agent_response+18`）；
- `services.reply(user_message, session_config, Some(cancel))`（`process_agent_response+28`）拿到 `BoxStream<AgentEvent>`；
- 循环 `stream.next()` 消费事件：本例纯文本 → 渲染 markdown，无 tool_confirmation / elicitation 分支（`process_agent_response+51` 之后）。

### 17 → reply

`reply`（`services.rs · reply+0`）：包一层 `with_session_id`，调 `start_reply`（`reply+10`），返回 `events.try_filter_map(user_event)`（`reply+19`，把非用户可见事件过滤掉）。

### 18 → start_reply

`start_reply`（`services.rs · start_reply+0`）：
- `user_message.with_generated_id_if_missing()`（`start_reply+6`）；
- 处理 ElicitationResponse 特例（本例无，跳过 `start_reply+20`）；
- 拿 `turn_guard` + `evicted`：`runtime.lock_lifetime` → `runtime.confirmations.session(&id).try_start_turn()` → `runtime.touch(&id)`（`start_reply+57~+66`）；`turn_guard.state().start_new_turn()`；
- `session_manager.add_message(&id, &user_message)`（`start_reply+78`）持久化用户消息；
- `disable_session_naming` 为假时后台 `maybe_update_name`（`start_reply+81`）；
- 调 `self.turn(session_config, cancel, turn_guard, true)`（`start_reply+102`）。

### 19 → turn

`turn`（`services.rs · turn+0`）返回 `async_stream::try_stream!`：
- `run_first=true` → 调 `services.run_machine(...)`（`turn+19`）拿流，消费其事件，收集 `tool_confirmation_request_ids`；
- 本例无确认 → `!has_confirmations` → `break`（`turn+31`）；
- `turn_end.finish()`（`turn+45`）。

### 20 → run_machine

`run_machine`（`services.rs · run_machine+0`）：
- `provider = self.provider(&session_id)`（`run_machine+7`）、`effective_model_config_for_session`（`run_machine+8`）；
- 读 session，取 `saved_provider_session_id`，`provider.resume(...)`（`run_machine+19`）、`provider.apply_model_selection(...)`（`run_machine+27`）；
- `get_context_limit(provider, model_name)`（`run_machine+35`）；
- `steer_queue = runtime.steer_queue(&id)`（`run_machine+38`）；
- `create_state_machine(provider, model_config, context_limit, session_config, cancel, steer_queue)`（`run_machine+39`）；
- 建 `mpsc` channel + `Emitter`，`run_goose(&machine, session_manager, &hook_manager, &session_id, &emit)`（`run_machine+58`），事件经 `tokio::select!` 从 `rx` 回传。

### 21→22 · 状态机构建

`create_state_machine`（`services.rs · create_state_machine+0`）→ `create_state_machine_with_lease`（`create_state_machine_with_lease+0`）：`TurnSettings::from_config` 取重试/压缩/停止钩子阈值，`capped_compaction_threshold`、`compute_tool_call_cutoff` 算压缩参数，最后 `build_state_machine(StateMachineConfig{...})`。

`build_state_machine`（`state_machine_builder.rs · build_state_machine+0`）按 `manages_own_context` 组装 operations（完整清单见 01；本例 provider 管理自己的 context → 跳过 ContextRelevance/Compaction），把 operations 包成 `Step::Operation`，末尾接 `Step::Inference(InferenceRunner)`，`StateMachine::new(steps, cancel)`。

### 23→24 · run_goose → StateMachine::run

`run_goose`（`session.rs · run+0`）：`runtime.load(session_id)` 读入口 session，`run_turn_start_hooks`，包 `TurnRuntime { session_manager, usage }`，调 `machine.run(&runtime, session_id, emit)`（`run+34`）。

`StateMachine::run`（`machine.rs · run+0`）循环：
```text
loop {
  session = runtime.load(session_id)          // 重载会话
  result = self.step(&session, emit)          // 跑 operations + inference
  self.apply(runtime, &session, &mut effects, emit)  // 应用 effects 落盘
  match result.status {
    Continuing => continue,
    Yielded | Cancelled => break,
  }
}
finalize(...)
```
`step`（`machine.rs · step+0`）遍历 steps，每个 operation 跑 `run()`，`InferenceRunner` 调 provider 流式推理，产出 `Message`/`Usage` effects。本例一次推理即回 `Yielded`。

### 25 → 事件回传

推理产生的 assistant `Message` 事件经 `Emitter`→`mpsc`→`run_machine` 的 `select!` 回传到 `turn`，再经 `reply` 的 `try_filter_map` 回给 CLI，`process_agent_response` 渲染。
